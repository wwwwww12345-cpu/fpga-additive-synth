# HC-04 串口字节协议 — FPGA 乐器控制台（v0）

> 版本：**v0.6**（2026-11-03，v0 基础上加 v0.1 音色 / v0.2 应答 / v0.3 单音 / v0.4 混响 / v0.5 滑音 / v0.6 灯带指引弹奏）· 小程序侧实现：`utils/protocol.js`（唯一定义处）· FPGA 侧见《FPGA对接说明.md》
> 数值可调，但**表结构不变**；任何改动先改 protocol.js 再同步本文档并升版本号。

## 1. 传输层

```
小程序 ──BLE(FFE1 write)──> HC-04 ──UART 115200 8N1──> FPGA RX
小程序 <──BLE(FFE1 notify)── HC-04 <──UART────────── FPGA TX
```
HC-04 是字节透传，不解析内容。BLE 默认 MTU 20 字节，小程序侧已做「单包 ≤20 字节、包间隔 ≥10ms」的串行队列（`utils/sender.js`）。UART 115200 下每字节约 87µs，BLE 侧节流对 FPGA 无压力。

## 2. 字节分工约定（硬约束）

| bit7 | 范围 | 含义 |
|---|---|---|
| 0 | 0x00~0x7F | **数据字节**（note/vel/dur/条目数等，天然 ≤127） |
| 1 | 0x80~0xFF | **命令字节**（帧头） |

任何数据流都不会被误认成命令；FPGA 解析器可随时用 bit7 重新同步。

## 3. 帧格式

帧 = **1 命令字节 + 0~3 数据字节**，单帧 ≤20 字节（当前最长 4 字节）。

| 命令字节 | 名称 | 数据字节 | 数据含义 | 方向 |
|---|---|---|---|---|
| `0x80` | PING | 0 | 连通性探测（FPGA 应回应答，见 §7） | → FPGA |
| `0x81` | 音域设置 | 1 | 偏移半音数 **+ 64**（64→0 半音；范围 −64~+63，即字节 0x00~0x7F） | → FPGA |
| `0x82` | 和弦设置 | 1 | 0=关，1=大三，2=小三，3=属七 | → FPGA |
| `0x83` | 音域重置 | 0 | 偏移归 0（兜底；压力传感器挡位也可改音域，两来源并存，此命令最后说算） | → FPGA |
| `0x84` | 演奏开始 | 0 | 从曲谱 RAM 起点开始播放（LED 指引同步启动） | → FPGA |
| `0x85` | 演奏停止 | 0 | 停止播放（保持当前位置；再次 0x84 从头开始，**待定**：是否支持暂停续播） | → FPGA |
| `0x86` | 音色切换 | 1 | **0=钢琴，1=吉他**（其他值按 1 处理）；复位默认钢琴 | → FPGA |
| `0x87` | 单音按下 | 2 | note(0~127，0 非法) / vel(1~127)；`vel=0` 在 FPGA 侧等价"松开"，**松开必须发 `0x88`** | → FPGA |
| `0x88` | 单音松开 | 1 | note(0~127) | → FPGA |
| `0x89` | 混响湿度 | 1 | 0 = 干声（混响全关），127 ≈ 全湿；**复位默认 32**（= 原来的固定 25% 湿声） | → FPGA |
| `0x8B` | 滑音（保留，本版未启用） | 1 | 音与音之间的 portamento：0 = 关（默认）；1 = 最快（≈50 ms 滑到）；127 = 最慢（≈1 s） | → FPGA |
| `0x90` | 曲谱开始 | 2 | 条目数 N：低 7 位 + 高 7 位（`N = d0 | (d1 << 7)`，N ≤ 512） | → FPGA |
| `0x91` | 曲谱条目 | 3 | note(0~127，**0=休止符**) / vel(1~127) / dur(1~127，单位 10ms) | → FPGA |
| `0x92` | 曲谱结束 | 0 | 下发完成，FPGA 校验条目计数后曲谱生效 | → FPGA |
| `0x93` | 演奏复位 | 0 | 演奏状态机/曲谱指针/LED 归零（区别于 0x85：停止且回起点） | → FPGA |
| `0x94` | 指引弹奏开始 | 0 | 用**已下发且 `0x92` 校验通过**的曲谱开始灯带指引；没有有效曲谱时 FPGA 回 NACK 码 4（**v0.6**） | → FPGA |
| `0x95` | 指引弹奏停止 | 0 | 退出灯带指引，灯带回默认显示，不改变曲谱/演奏状态（**v0.6**） | → FPGA |

## 4. 曲谱数据模型与下发序列

```
song = { name: string, entries: [{note, vel, dur}] }   // 条目上限 512（FPGA 曲谱 RAM）
```

下发 = 串行发送帧序列：

```
0x90 [N低 N高]  →  0x91 [note vel dur] × N  →  0x92
```

之后可随时发 `0x84 演奏开始 / 0x85 停止 / 0x93 复位`。

下发成功后还可以发 `0x94 指引弹奏开始 / 0x95 停止`（v0.6）：不自动演奏，而是用灯带**一步一步教人弹**（见 §5.6）。

### 示例字节流（下发 2 条的曲谱并开始演奏）

```
90 02 00            曲谱开始，N = 2
91 3C 60 32         条目#1 note=60(C4) vel=96 dur=50(500ms)
91 3C 60 32         条目#2 note=60      vel=96 dur=50(500ms)
92                  曲谱结束
84                  演奏开始
```

其他常用帧的线上字节：

```
80                  PING
81 4C               音域 +12 半音（76 = 12 + 64）
81 40               音域 0（64 = 0 + 64）
82 01               和弦=大三
82 00               和弦=关
86 00               音色=钢琴
86 01               音色=吉他
87 3C 60            单音按下：note=60(C4) vel=96
88 3C               单音松开：note=60(C4)
89 20               混响湿度=32（约 25% 湿，等于复位默认）
89 00               混响关（干声）
8B 00               滑音关（默认）
8B 40               滑音 64/127（中等，越往右越慢）
83                  音域重置
85                  演奏停止
93                  演奏复位
94                  指引弹奏开始（需要已下发成功；否则 FPGA 回 A2 14 04）
95                  指引弹奏停止
```

## 5. 关键设计决策

1. **dur 上限 127 而非 255**：数据字节必须 bit7=0，255 会撞上命令字节空间。dur 单位 10ms，单条最长 1270ms；**更长时值用连续多条同音条目拼接**（FPGA 侧对「同 note 连续条目」做音符延长即可，见对接说明）。若将来确需单条 >127，引入扩展帧（**待定**）。
2. **音域用偏移量而非绝对八度**：FPGA 不知道「当前基准」，偏移（±半音）语义无歧义；UI 上 ±1/±12 步进，`0x83` 做兜底归位（与压力传感器挡位并存）。
3. **条目数拆 2×7bit**：512 = 0x400，需要 10 bit，拆成低/高各 7 位仍满足数据字节 ≤127。
4. **旧 ASCII 协议（"60+"/"60-"）只在 demo 自测页保留**，不走本协议；正式控制台全部二进制。
5. **单音的力度归属（2026-10-31 定稿）**：`0x87` 帧里仍带 vel，但**力度由 FPGA 侧的 FSR 决定**——
   手机没有压力传感器，按多重它不知道。固件在收到 `0x87` 的同一拍用 FSR 的实时读数当力度：
   `push_vel = ble_note_acc ? fsr_vel : 96`，其中 `fsr_vel` 取 AIN0 最近一次采样的 `code[15:8]`（满压 ≈103，
   钳 1..127）；**读到 0（没接 FSR / I2C 死了）就回退到帧里的 vel 字节**，所以不接 FSR 也照常出声。
   小程序固定发 96，正好就是那个回退值。
   - 固件实现：`rtl/top_ble_fsr.v`（BLE 单音 + FSR 力度 + `top.FSR_KEYS_EN=0` 关掉 FSR 自己的键事件）
     → `bitstream/top_ble_fsr.fs`。仿真 `tb/tb_ble_fsr_vel.v` 10/10：`87 3C 60` + FSR=0x4E20 → vel=0x4E。
   - 已知边界：FSR 四通道一轮 ≈6.05 ms，按下那一拍用的是"最近一次 AIN0 采样"，最坏差一个轮次；
     `code[15:8]` 口径下 3.3V 满量程只到 103；`FSR_KEYS_EN` 默认 1 ⇒ 既有变体逐位不变。要"手机按键、FSR 给力度"需要固件改这一处。
   - **力度的四层映射：2026-11-01 用探针 `bitstream/top_fsr_vel_probe.fs` 实测后定稿**（用户板，10k 下拉）：

     | code 区间（AIN0） | 电压 | 力度 `v = code>>8` | 层 `L = v>>5` |
     |---|---|---|---|
     | 0000 ~ 00FF（静息/没接） | < 0.03 V | **回退 96**（帧里的值） | L3 |
     | 6000 ~ 8191（刚过 TH_ON） | 0.75 ~ 1.02 V | 23 ~ 31 | L0 |
     | 8192 ~ 16383 | 1.02 ~ 2.05 V | 32 ~ 63 | L1 |
     | 16384 ~ 24575 | 2.05 ~ 3.07 V | 64 ~ 95 | L2 |
     | 24576 ~ 26490（满压） | 3.07 ~ 3.31 V | 96 ~ 103 | L3 |

     实测四点：轻按 `0x1D1B~0x240D`(7451~9229)、中 `0x5585`(21893)、重 `0x6014`(24604)、全力 `0x677A`(26490)；
     静息 `0x000F~0x00B1`。**中档以上 FSR 已接近饱和**（21893→26490 只差 4%），这一档差异用户已接受，
     映射保持 `v=code>>8` / `L=v>>5` **不再改**（引擎 `VEL_LAYERS=4`、`VEL_SHIFT=5`）。
     四层都碰得到：轻 → L0/L1、中 → L2、全力 → L3；不碰 FSR 时回退 96 正好落 L3，所以"没接 FSR 也照常响"。
     测量工具（只发不收）：`bitstream/top_fsr_vel_probe.fs`，TX=G1、115200 8N1、100 ms 一行 `c=… v=… L=… pm=… pv=… pl=… n=…`。
6. **灯带指引弹奏（v0.6，`0x94` / `0x95`）**：不是"自动演奏"，而是用灯带一步一步教人弹。
   - 灯语：目标音灯**黄**；按对 → 该灯**绿**并保持到松开；松开 → 下一个音**黄**；按错 → 该灯**红** 0.5 s 后回黄；
     休止符（`note=0`）自动跳过；走到曲末自动结束（灯带全灭）。
   - **前置条件**：只认 `0x92` 校验通过（`song_valid=1`）的曲谱。没有有效曲谱就发 `0x94` → **NACK 码 4**。
     所以小程序必须等整批下发帧全部写成功才把「指引弹奏」按钮点亮；重新下发（`0x90`）一开始就要把本地 `songValid` 清掉。
   - **隐式退出**：`0x84` 自动演奏开始 / `0x90` 重新下发 / `0x93` 复位 都会让指引退出（三者清 `song_valid` 或直接拉 stop）。
   - **灯带 24 颗**对应 MIDI 60~83（C4~B5）：超出这个范围的音**不亮灯，但流程照走**（指针照样前进），
     所以音域偏移拉大了以后可能出现"某些音没灯"——这是设计行为，不是丢帧。
   - RTL：`rtl/ble_cmd.v`（`C_GSTR/C_GSTP` → `guide_start/guide_stop` 单拍脉冲）+ `rtl/guide_ctrl.v`（状态机）。
     ⚠ 已知缺口（2026-11-03 记录，FPGA 侧待接）：`rtl/ack_tx.v` 目前只对 `0x80`/`0x90`/`0x92` 回包，
     RTL 已接通：`guide_ctrl.v` 已实例化于出货顶层 `lowlat/top_ble_fsr_keys.v`；`ack_tx.v` 已转发 0x94 的失败应答（`A2 14 04`）。其他旧顶层（`top_ble_fsr.v` 等）未接指引，属历史文件。
     （现在顶层挂的还是 `led_guide.v`）。在此之前的兼容做法：小程序以本端 `songValid` 为准，不依赖回包。

## 6. 小程序侧实现约束

- 所有命令字节/常量集中 `utils/protocol.js`，页面禁止魔法数字。
- 发送一律走 `utils/sender.js` 全局队列（串行、≤20 字节/包、≥10ms 间隔、批量失败即丢弃剩余帧防半截曲谱）。
- encode/decode 为纯函数；`protocol.selfTest()` 做 encode→decode 往返自测（模拟器测不了 BLE，这是唯一自动化验证）。

## 7. FPGA → 小程序应答（v0.2 已实现）

帧格式与 §3 同构：**命令字节 bit7=1 + 0~2 个数据字节（数据字节 bit7=0）**。

| 命令字节 | 名称 | 数据字节 | 含义 |
|---|---|---|---|
| `0xA1` | ACK | 1 | 被确认命令的**低 7 位**（`cmd & 0x7F`），接收方 `| 0x80` 还原。例：`92` 成功 → `A1 12` |
| `0xA2` | NACK | 2 | 出错命令的低 7 位 + 错误码。例：`90` 的 N 超范围 → `A2 10 02` |
| `0xA0` | 状态回显 | 2 | **仍未实现**（音域偏移 + 和弦模式，留给二期 UI 同步） |

**为什么要取低 7 位**：数据字节必须 bit7=0，若直接写 `A1 92`，对端会把 `92` 当成新命令（本机 2026-10-24 的仿真就是这样抓出来的）。所以载荷统一为 `cmd & 0x7F`。

错误码：

| 码 | 含义 |
|---|---|
| 1 | 条目数不符（`0x92` 时已写入条数 ≠ `0x90` 声明的 N） |
| 2 | N 超范围（N>512 或 N=0） |
| 3 | 不在下发期就发了 `0x92` |
| 4 | 未下发曲谱 / 曲谱无效（`0x94` 指引弹奏要求曲谱已通过 `0x92` 校验；**v0.6** 新增，`ble_cmd.v` 产生、`ack_tx.v` 已转发） |

**回哪些命令**（刻意只回有结果意义的）：

| 上行命令 | 应答 |
|---|---|
| `0x80` PING | 总是回 `A1 00` |
| `0x90` 曲谱开始 | 成功不回；失败回 `A2 10 02` |
| `0x92` 曲谱结束 | 成功 `A1 12`；失败 `A2 12 01/03` |
| `0x94` 指引弹奏开始 | **当前静默**（`ble_cmd.v` 已置错误码 4，但 `ack_tx.v` 未转发；接上后失败应为 `A2 14 04`） |
| 其它（`0x81/0x82/0x83/0x84/0x85/0x86/0x87/0x88/0x91/0x93/0x95`/未知） | **静默**（幂等或即时，回包只会刷满日志） |

RTL：`rtl/ack_tx.v`（组包/发送）+ `ble_cmd.v` 的 `evt_we/evt_cmd/evt_code` 事件；ACK 在蓝牙 TX 上**优先于回显**，回显因此顺延一拍而不丢字节。
小程序：`protocol.js` 的 `CMD.ACK/NACK`、`CMD_DATA_LEN`、`describeFrame`、`ackReason()`；`index.js` 只把 `0xA0~0xA2` 当真正下行，其余帧标记为"回显"。
